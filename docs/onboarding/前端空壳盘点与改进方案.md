# 前端空壳盘点：以 AI 核心能力为准

> 盘点口径：不问"按钮点不点得动"，只问**后端已有的 AI 能力，前端能不能看见**。
> 一个按钮没有 onClick 只是体验问题；一个页面用假数据冒充 AI 输出，是答辩会被问穿的问题。

---

## 一、一句话结论

后端有 **14 项已实现的 AI 能力**，前端真正可见的只有 **4.5 项**；10 个页面里 **只有 1 个**（`/` 对话页）接通了真实链路，其余 9 个全部由 `frontend/lib/data.ts` 的 171 行硬编码喂着。

最隐蔽的一处不是页面，而是**多轮对话是假的**：`ChatContainer.tsx:55` 写死 `sendChat(question, [])`，后端 `identify_node` 和 `DomainAgent.answer` 都支持 history，前端一次也没传过。

| 11 | **「编造 vs 未召回」区分** | `check_citation_accuracy` 返回 `unretrieved` | ❌ `streamer.py:21-25` 未传 | ❌ | 审查 Agent 最亮的能力被丢弃 |

| 13 | **审查反馈内容** | `feedback` 拼进重生成 prompt | ❌ | ❌ | 只看到"打回了"，看不到"改了什么" |

> 其中 **#4 多轮、#9 溯源、#14 耗时** 三项是**后端零改动或十几行改动就能激活**的，投入产出比最高。

## 四、四处「伪 AI」——最危险的部分

### 1. 假的多智能体时间线（`ConsultationView.tsx:93-104`）

```tsx
{agentEvents.map((event) => ( ... ))}
// data.ts:119-125
{ name: "接案代理", status: "completed", elapsed: "02 秒", ... },
{ name: "规划代理", ... }, { name: "检索代理", ... },
{ name: "推理代理", status: "active", elapsed: "18 秒", ... },
{ name: "审查代理", status: "queued", elapsed: "-", ... }
```

问题：
- 后端只有 **4 个节点 / 3 个角色**（identify → 5 领域节点 → review），没有"规划代理""推理代理"
- 耗时 `02 秒 / 05 秒 / 11 秒 / 18 秒` 是编的（真实数据在 `elapsed_ms` 里）
- `status: "active"` 永远不动，页面看起来"正在推理"，其实什么都没发生

**这是答辩时最容易被戳穿的地方**：面试官问"你的规划 Agent 做了什么"，代码里没有这个东西。

### 2. 假的运维指标（`data.ts:166-171` + `admin/page.tsx`）

```
知识库新鲜度 92%  · 图谱覆盖 18.4k  · 检索延迟 740ms  · 失败任务 2
```

真实值（本次实测）：

| 指标 | 页面写的 | 实际 |
|---|---|---|
| 图谱规模 | 18.4k | **21,073**（Law 3,942 + Case 17,131）+ 19,645 边 |
| 检索延迟 | 740ms | 可实测（hybrid 约 300~600ms） |
| 知识库 | "18 分钟前同步" | 法条 3,942 / 24 部法规，可现算 |

**真实数字比编的更好看**，却用了假数据。

### 3. 假的知识图谱（`GraphExplorer.tsx` + `data.ts:150-164`）

页面画的是 5 个节点、5 条边，标签「劳动合同法 39 条」「上海二中院案例」。库里是 17,131 个真实案例 + 3,942 条法条 + 19,645 条 `APPLIES` 边。

GraphRAG 是这个项目最强的标签，而它唯一的可视化页面是画上去的。

### 4. 假的多轮对话（`ChatContainer.tsx:55`）

```tsx
const response = await sendChat(question, []);   // ← 永远传空
```

`messages` state 里明明存着全部历史，却不传。后果：

- 「那要赔多少钱？」这类追问，模型收不到上一轮的问题和答案
- 后端 `identify_node` 的 history 拼接逻辑、`DomainAgent` 的 history 参数，全部形同虚设
- **5 行代码就能修好**，但当前所有"多轮对话"的演示都是单轮

## 五、空壳清单（精确到文件）

源码中 **15 处** `<button>` 标签无 `onClick`。因为多处写在 `map` 里，实际渲染出 **约 40 个**点了没反应的按钮。

| 位置 | 元素 | 渲染数量 | 说明 |
|---|---|---:|---|
| `analysis/[id]/page.tsx:21-23` | 编辑 / 固定 / 引用 | 12 | 4 张卡 × 3 |
| `matter/MatterHeader.tsx:21-26` | 保存 / 导出 | 8 | 每页 2 个 × 4 页 |
| `matter/MatterHeader.tsx:45` | 大纲 5 项 | 5 | 无跳转锚点 |
| `workspace/page.tsx:54` | 事项模板 ×3 | 3 | 无 onClick |
| `graph/GraphExplorer.tsx:72-77` | 适应画布 / 重置 | 2 | 无 onClick |
| `graph/GraphExplorer.tsx:96` | 查看证据 | 1 | 无 onClick |
| `consultation/ConsultationView.tsx:81-86` | 添加附件 / **发送** | 2 | **发送是最伤的一个** |
| `evidence/EvidencePanel.tsx:26` | 来源卡片 | 9 | 是 `<button>` 但点击不切换，`selectedId` 由外部常量传入 |
| `shell/AppShell.tsx:60` | 通知 | 10 | 每个页面都有 |

死输入（4 类）：

| 位置 | 元素 | 问题 |
|---|---|---|
| `workspace/page.tsx:30` | 搜索事项 | 无 `onChange` |
| `history/page.tsx:16` | 筛选事项 | 无 `onChange` |
| `shell/AppShell.tsx:57` | Ctrl K 搜索 | 无 `onChange`，快捷键也没绑 |
| `graph/GraphExplorer.tsx:23` | 实体检索 | 无 `onChange` |

写死不可交互（2 处）：

- `GraphExplorer.tsx:35` 展开层级 `readOnly value="2"` —— 永远是 2
- `GraphExplorer.tsx:26` 「法条与争点」`checked readOnly` —— 永远勾着

**动态路由参数被完全忽略**：`app/analysis|consultation|evidence|graph/[matterId]/page.tsx` 里 `params` 一次都没用，全部渲染 `currentMatter`。实测 `/consultation/contract-review` 显示的仍是「试用期解除与赔偿风险评估」。

## 六、改进方案

### P0 · 半天 · 消灭「伪 AI」，零后端改动

| # | 改动 | 文件 | 工作量 | 验收 |
|---|---|---|---|---|
| 1 | **修多轮对话** | `ChatContainer.tsx:55` | 5 行 | 追问「那要赔多少钱」能接上文 |
| 2 | 删除假智能体时间线 | `ConsultationView.tsx:93-104` + `data.ts:119-125` | 删 | 页面不再出现不存在的"规划代理" |
| 3 | 删掉 admin 假指标，改为"待接入"或真实值 | `admin/page.tsx` | 20 行 | 页面无虚构数字 |
| 4 | workspace / history 搜索框接本地过滤 | 两个 page | 各 10 行 | 打字能筛 |
| 5 | settings 三个开关写 `localStorage` | `settings/page.tsx` | 15 行 | 刷新保持 |
| 6 | 暂时禁用而非留空：保存/导出/添加附件/通知 | 各处 | 加 `disabled` + title | 点了至少给反馈 |
| 7 | `[matterId]` 读取 `matters` | 4 个动态页 | 各 5 行 | 不同 id 显示不同事项 |

**第 1 项最优先。** 它不删任何东西，只是把一个已有的能力打开。

```tsx
// ChatContainer.tsx
const history = messages
  .filter((m) => m.role === "user" || m.role === "assistant")
  .map((m) => ({ question: m.role === "user" ? m.content : "", answer: m.role === "assistant" ? m.content : "" }));
// 更稳的做法：成对构造，用 prevQuestion 变量跟踪上一轮
const response = await sendChat(question, historyPairs);
```

### P1 · 1~2 天 · 激活后端已有能力（后端各十几行）

| # | 改动 | 后端 | 前端 | 价值 |
|---|---|---|---|---|
| 8 | **结构化来源** | `streamer.done_event` 增 `sources_detail: [{type, law_name, article_number, case_id, crime, judgment, fact, retrieved_by, score}]` | `AssistantMessage` 把 `<li>` 换成可展开卡片 | 溯源从"一行字"变成"可点开的证据"，**答辩最加分** |
| 9 | **逐节点耗时** | 已有 `elapsed_ms` | 时间线每步右侧显示 `1.2s` | 性能可视，5 行 |
| 10 | 关键词透出 | `chat.py:54` 加 `keywords` | 时间线加「检索词」chip | 展示查询理解 |
| 11 | 审查的未召回项 | `streamer.py` 透传 `unretrieved` | 审查 chip 展开显示 | 展示审查 Agent 的差异化 |
| 12 | 审查反馈内容 | `chat.py:77` 加 `feedback` | "第 2 版"hover 显示改了什么 | 反思回路可见 |

第 8 项是重点。现在 `build_sources()` 把结构化 metadata 压成 `"中华人民共和国刑法 第二百三十四条"` 这种一句话，前端只能 `<li>{src}</li>`。而后端 `Document.metadata` 里 `case_id / crime / judgment / fact` 全都有——**数据一路传到 `done` 事件门口，最后一步被压扁了**。

### P2 · 3~5 天 · 让 mock 页变成真功能（需新接口）

| # | 新接口 | 替代 | 说明 |
|---|---|---|---|
| 13 | `GET /api/graph/{article_number}?hop=2` | `graphNodes` 5 个硬编码 | 从 Neo4j 拉真实子图，**GraphRAG 的门面** |
| 14 | `GET /api/stats` | `adminMetrics` 假数字 | Neo4j count + 语料条数 + 索引大小，20 行 |
| 15 | `GET/POST /api/matters` | `matters` 硬编码 | SQLite 或 JSON 文件，让 workspace/history 真实 |
| 16 | `GET /api/cases?crime=xxx` | `evidenceItems` 假证据 | 类案列表页 |
| 17 | 类案评测脚本 | 无 | `accusation` 是现成 ground truth，出 Recall@K |

**P2 里只做 #13 一项也值**：17,131 个真实案例的图，比任何文字描述都有说服力。

## 七、建议顺序

如果目标是**答辩/简历**，我建议：

1. **P0-1（多轮对话）** —— 5 行，修掉最隐蔽的假象
2. **P1-8（结构化来源）** —— 半小时，把溯源能力真正露出来
3. **P1-9（耗时）** —— 5 行，时间线立刻有"工程感"
4. **P2-13（真实图谱接口）** —— 半天，GraphRAG 从标签变成画面
5. P2-14（真实指标）—— 20 行，把假数字换成更好的真数字
6. 其余 P0 收尾

前四项加起来约一天，能覆盖答辩时 **80% 的追问点**（多轮、溯源、性能、图谱）。
