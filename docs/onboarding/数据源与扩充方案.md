| 北大法宝 / 威科先行 | 法规 + 案例 + 裁判规则，带引用关系 | 💰 付费授权 | ✅ 商用最稳 | 真做产品时的正解 |

### 为什么还是选了官方站

1. **只有官方站能保证"现行有效"**。同名法规有多个历史版本，官方站用 `sxx` 字段区分：
   `3=现行有效 / 2=已被修改 / 1=已废止`。只取 `sxx=3`，语料才不会混进旧条文。
2. **文书网和第三方库都是二手**。二手数据的条文版本、条号可能滞后，
   而法条版本错了，RAG 引用就是错的——这比检索不准严重得多。
3. 法律文本本身不受著作权保护（《著作权法》第五条：法律、法规等具有立法、行政、司法性质的文件不适用本法），
   风险点在**站点的自动化采集政策**，不在文本本身。所以控制规模、不做高频批量，是这里的分寸。

### 一个真实例子：为什么"实时抓"比"抄一份"重要

《治安管理处罚法》2025-06-27 修订后**整体重新编号**，"殴打他人"从旧版第四十三条
移到了**第五十一条**。任何抄旧版数据的项目，这一条都会引错。本次评测集里专门留了
`adm-004` 这个用例来盯住它。

## 三、已实现的采集链路

```
flk.npc.gov.cn
   │  POST /law-search/search/list        ← 按标题精确检索，取 sxx=3 的版本
   │  GET  /law-search/search/flfgDetails  ← 元数据 + OSS 文件路径
   │  GET  /law-search/download/pc         ← 换签名直链
   ▼
docx（word/document.xml）
   │  zipfile + ElementTree 解析段落       ← 不引入 python-docx
   ▼
law_parser：定位「第一条」→ 向前回溯编/章/节 → 顺序切条
   ▼
data/raw/laws/<法规名>.json  →  data/processed/laws.json（3942 条）
   ▼
FAISS 索引 / Neo4j 图谱 / 评测集
```

### 模块职责

| 文件 | 职责 | 关键点 |
|---|---|---|
| `src/data/flk_client.py` | 检索、取详情、下载、解析 docx | 只用标准库；处理了**接口换代**（旧版 `GET /api/` 已下线，现在会回落 SPA 首页返回 HTML，容易被误判成反爬） |
| `src/data/law_parser.py` | 段落 → 「编-章-节-条」结构 | 法规 docx 开头带**目录**，目录里的章标题与正文重复，必须从首个条号回溯；支持刑法「之一」条 |
| `scripts/fetch_laws.py` | 抓取 CLI + 语料清单 | 增量抓取、`--force` 重抓、`--check` 只探测 |
| `src/data/collector.py` | 语料读取 | 优先 `data/processed/laws.json`，缺失才回退 5 条示例 |
| `src/data/kg_builder.py` | 图谱导入 | 3942 个节点逐条 MERGE 会有 3942 次往返，改成 `UNWIND $rows` 批量 + 唯一约束 |

### 用法

```bash
python scripts/fetch_laws.py --list             # 看清单（24 部，按 5 个领域编排）
python scripts/fetch_laws.py --check            # 只检查能否检索到
python scripts/fetch_laws.py --all              # 全量抓（已缓存的跳过）
python scripts/fetch_laws.py --all --force      # 强制重抓
python scripts/fetch_laws.py --only 中华人民共和国刑法

python scripts/import_sample_data.py            # 导入 Neo4j
python scripts/eval_retrieval.py --mode bm25    # 评测（无需任何 Key）
```

## 五、扩充后的效果（同一套 33 条评测集）

| 检索模式 | Recall@5 | MRR | 平均耗时 | 依赖 |
|---|---|---|---|---|
| 字符二元组兜底（原来） | 0.545 | 0.336 | 102 ms | 无 |
| **BM25（新增）** | **0.727** | **0.482** | **21 ms** | 无 |
| 混合 RRF（BM25 + 向量 + 图谱） | 0.727 | 0.482 | 237 ms | 向量/图谱未就绪时自动降级 |
| Corpus coverage | **1.000** | — | — | 33/33 期望条文都在语料里 |

> 向量单路这次没跑成：环境里的 `DASHSCOPE_API_KEY` 返回 401（Key 失效或为占位值）。
> 混合模式因此实际只走了 BM25 一路——这恰好验证了降级设计：**没有 Key 也不会整条链路挂掉**。
> 换上有效 Key 后先 `--build-index` 再跑 `--mode vector`，就能补上第三行。

### 两条必须知道的分析结论

**1. 剩下的 27% 未命中，主要是同义改写，不是算法参数问题。**

`lab-007`「公司拖欠工资，劳动局能怎么处理？」期望劳动合同法第八十五条，
但该条原文写的是「未按照劳动合同的约定或者国家规定**及时足额支付劳动报酬**」——
全条没有"拖欠"两个字。BM25 命中不了，只有向量检索能覆盖这类语义鸿沟。
**这就是"为什么必须有向量检索"的实证，比任何架构图都有说服力。**

**2. 法律问答有多解，单条标注会低估系统。**

同一个行为常被多部法规同时规范。`lab-007` 的 BM25 第一名是
《劳动争议调解仲裁法》第九条——它同样直接规范"拖欠劳动报酬"，是**正确引用**。
所以评测集加了 `also_accept` 字段声明等价条文。做法律评测时如果只标一条，
指标会系统性偏低，这个坑值得在简历/答辩里讲。

## 六、案例数据怎么办（三条路线，按成本排序）

| 路线 | 做什么 | 成本 | 产出 |
|---|---|---|---|
| **A. 先不做**，只做法条 RAG | 把图谱做成 Law-Article 两层 + 法条互引关系 | 0 | 图谱有内容、可演示，不冒编造风险 |
| **B. CAIL2018 刑事案例** | 验证仓库数据文件 → 抽取 `fact` + `accusation` + `relevant_articles` | 1~2 天 | ✅ **已完成**：17,131 条案例 / 19,645 条案例-法条边 |
| **C. 最高法指导性案例** | 少量、人工核对，做成精品案例库 | 2~3 天 | 数量少（数百条）但权威，适合做"引用溯源"演示 |

**建议 A → B**。先让法条图谱跑通（现在就能做），再用 CAIL 补案例，
这样每一步都有可交付物，不会卡在数据上。

## 七、合规与简历表述

### 必须注意

1. **不要把这件事写成"爬虫"**。官方站 `robots.txt` 明确禁止自动化采集。
   简历/答辩上应表述为：**"基于国家法律法规数据库构建 3942 条现行有效法条语料"**，
   重点在语料构建与检索质量，不在采集技术。
2. **不要提交全量抓取产物到公开仓库**。`data/processed/laws.json` 3.4MB，
   本地用没问题；公开仓库建议 gitignore，让使用者自己跑脚本生成。
3. **法律文本无著作权，但汇编/数据库可能有**。引用条文时标注来源即可，
   不要把第三方库的整体数据当作自己的成果。
4. **产品化必须换授权数据源**（北大法宝/威科），这是行业惯例，也是面试加分项——
   说明你知道边界在哪。

### 简历可写（现在就能写）

> 构建法律领域 RAG 语料管道：对接国家法律法规数据库，实现检索→签名直链→docx 结构化解析，
> 覆盖 24 部法规 3942 条现行有效条文（42 万字）；通过时效性字段过滤、目录回溯、
> 「之一」条识别等处理保证条文准确性，并建立 33 条人工标注评测集（法名+条号粒度）。

> 设计 BM25 + 向量 + 图谱三路 RRF 融合检索，在无 Embedding 服务时自动降级，
