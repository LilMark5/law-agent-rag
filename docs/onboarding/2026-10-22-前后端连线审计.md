# 前后端连线审计（2026-10-22 22:3x）

> **口径**：只问一件事——页面上的数字/文案/列表，是不是从真实数据源流过来的（`/api/*` 或真实计算）。
> 按钮没 onClick 只是体验问题；用假数据冒充 AI 输出，是面试/演示会被当场问穿的问题。
> 本文替代 `前端空壳盘点与改进方案.md`（19:3x 版）中已修复的条目。

## 2. 五处"假得最危险"的地方

按「演示时被点开就穿帮」的概率排序：

### ① 咨询页的智能体时间线是编的
`components/consultation/ConsultationView.tsx:93-104` 渲染 `agentEvents`，数据在 `lib/data.ts:119-125`：

```
接案代理 02 秒 / 规划代理 05 秒 / 检索代理 11 秒 / 推理代理 18 秒 / 审查代理 -
```

这五个 agent **在 `src/agents/graph.py` 里一个都不存在**（真实节点是 `identify / retrieve / 5 个领域节点 / review`），耗时是手写的字符串，`status` 永远停在 `active / queued` 不动。
→ 和大模型回答同屏出现，最容易被追问「这是哪个框架的 trace」。**必须删或换成真实 trace。**

### ② 三个整页 + 一个右栏，喂的是同一个虚构案件
`lib/data.ts` 里 `currentMatter` 是「试用期解除与赔偿风险评估（上海）」，`matters` 另外编了 3 个（SaaS 协议 / 股权激励 / 个人信息合规），`evidenceItems` 3 条、`citations` 3 条、`messages` 4 条——**全部是虚构的**，包括 "上海二中院 2023-08-11 判例" 这种看起来很像真的元数据。
→ 法条/案例是可核验内容，编造判例比编造按钮严重得多。

### ③ 咨询页的「发送」根本没有提交逻辑
`ConsultationView.tsx:81-87`：`添加附件`、`发送` 两个 button **都没有 onClick**，`type="button"`；textarea 有 `onChange` 但 form 没有 `onSubmit`。
→ 用户输完字点发送，什么都不会发生。而这个页面恰恰是「看起来最像核心功能」的那个。

### ④ 设置页承诺了一个不存在的持久化
`app/settings/page.tsx:13-21`：3 个 `input type="checkbox"` 用 `defaultChecked`，没有 `useState`、没有 `localStorage`，而旁边的说明文字写着「该偏好保存在本地」。
→ 刷新即还原，文案与行为不符。这是**唯一一处"谎报能力"的文案**。

### ⑤ 工作台的运营指标是编的
`app/workspace/page.tsx:59-68`：

- `92%` 知识库新鲜度 + 「18 分钟前同步，2 个采集任务待复核」
- 「图谱检索在线」+「2 个数据源导入失败」

真实情况：语料是离线一次性导入的，没有同步任务、没有采集任务，图谱状态应该问 `/api/graph/stats`（`available` 字段）。这些数字**每一个都没有来源**。

## 4. 动态路由是摆设

`app/{consultation,analysis,evidence,graph}/[matterId]/page.tsx` **四个文件全都没有解构 `params`**（grep `params` 零命中），全部直接渲染 `currentMatter`。

→ `/consultation/contract-review` 和 `/consultation/anything-else` 显示的是同一份「试用期解除」内容。
→ 连带后果：工作台/历史里 4 张卡片的链接都指向不同 id，但点进去内容完全一样。

## 5. 后端已经有、前端还没接的（低成本补分项）

| 能力 | 后端在哪 | 前端状况 |
|---|---|---|
| `keywords` 关键词抽取 | `graph.py:48,77,93` 已在 state 里 | `chat.py:54-62` 的 intent 事件没带 → 前端永远看不到 |
| `unretrieved`（存在但未召回）与编造的区分 | `reviewer.py:122` 已算 | `chat.py:78-87` 与 `streamer.py:26-31` 都没发 |
| 结构化引用原文 | `sources_detail` 已发 | ✅ 对话页已消费；但 **`/evidence` 页仍是假证据**，两边不共用 |
| 子图/二跳 | `/api/graph/subgraph` 已实现 | ✅ 只用在 `/graph`；咨询/证据页没有接（点击引用无法看到原文或关联） |
| 逐节点耗时 | `elapsed_ms` 已发 | ✅ 已接（`timings` 相邻相减） |

**判断**：对话页已经吃满 SSE，真正的缺口在**其它页面没有复用对话页的能力**——不是缺后端，是缺连线。

## 6. 修复优先级

| 优先级 | 动作 | 代价 | 收益 |
|---|---|---|---|
| **P0** | 删掉 `ConsultationView` 的假 5-agent 时间线，换成 `<AgentTimeline>`（或直接不显示） | 删 20 行 | 消灭最大的「伪 AI」 |
| **P0** | 咨询页改为复用 `ChatContainer`（真 SSE），或把「发送」接到 `/api/chat` | 中 | 同时解决假消息、假引用、2 个死按钮 |
| **P0** | settings 三个开关接 `localStorage`（或删掉「保存在本地」的文案） | 10 行 | 消除唯一一处谎报 |
| **P1** | workspace 的假指标换成 `/api/graph/stats` 的 `available` + 真实条数；删「采集任务」类文案 | 20 行 | 少 4 个无源数字 |
| **P1** | `MatterHeader` 的保存/导出改 `disabled` + `title="尚未实现"`，分析页 12 个按钮同处理 | 小 | 从「点了没反应」变「明确不可用」 |
| **P2** | 加 `GET /api/matters`（哪怕先返回空列表），workspace/history 走「空态 + 去对话」 | 中 | 让页面结构立得住，不再撒谎 |
| **P3** | SSE 补 `keywords` / `unretrieved`，时间线展示关键词与「未召回」提示 | 小 | 可解释性 +1 |
| **P3** | 4 个 `[matterId]` 页真正读取 `params`（P2 之后才有意义） | 小 | 路由不再形同虚设 |

> 取舍判断：**删假数据比补真接口便宜十倍**。P0 三项都不需要新接口，做完立刻能对外说「这个项目没有一处假数据」。

## 7. 复核方法（下次自己验一遍）

```bash
# 1. 后端到底有几个端点
grep -rnE "@router\.(get|post)" backend/routers/*.py

# 2. 哪些前端文件还在吃 mock
grep -rln "lib/data" frontend/app frontend/components

# 3. 哪些文件真的调了 API
grep -rln "from \"@/lib/api\"" frontend/app frontend/components

# 4. 死按钮：有 <button> 无 onClick
for f in $(find frontend/app frontend/components -name "*.tsx"); do
  n=$(grep -c "<button" "$f"); c=$(grep -c "onClick" "$f")
  [ "$n" -gt 0 ] && echo "$f: button=$n onClick=$c"
done

# 5. 动态路由是否读了 params
grep -rn "params" frontend/app --include=page.tsx
```
